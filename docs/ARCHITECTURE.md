# Architecture

React/TypeScript/Vite serves five views. FastAPI serves the built frontend and
same-origin JSON API. PostgreSQL owns all authoritative records. A separate
Python worker polls durable schedules and claims queued runs. No browser timer
executes tasks. No Redis or second scheduler is required.

Feature modules under `commander/` separate authentication, memory, connections,
provider HTTP, action policy, inference budgets, runs and scheduling. SQL is
parameterized through psycopg. Pydantic rejects extra input fields. OpenAPI
response contracts generate frontend types in `frontend/src/api-schema.d.ts`.

A model can propose a typed operation. The broker checks skill scope, owner,
connection revision and active lease before dispatch. It cannot grant itself
permissions. Only the configured repository and approved search domains are
available. Network destinations are hard-coded provider HTTPS hosts; redirects
are disabled. Search-result pages are not fetched by this server.

Approval commits the action and queued continuation together. External writes
persist intent before dispatch. GitHub has no assumed idempotency key: a unique
marker supports bounded read-only reconciliation after an uncertain response.
There is no general exactly-once promise. Cancellation stops future dispatch and
cannot undo a request already sent. Revoke/cancel and dispatch serialize using
an owner advisory lock. One active run per owner bounds model concurrency.

Schedules record UTC instants and IANA display zones. Recurrence means elapsed
seconds, not fixed local wall time; daylight-saving changes can shift displayed
hours. Missed intervals coalesce into one run. Unique schedule/occurrence keys
and transactional locks prevent duplicate occurrence creation. Three read-only
attempts are the crash-recovery limit. Writes and note intents are not blindly
repeated.

The `commander` schema is independent of the existing `public` draft schema.
See ADR 001. Session and provider secrets never enter frontend storage or model
parameters. Local storage is owner controlled; selected context leaves the host.

## Configuration flow

SettingsPage → authenticated settings/models/system routes → preferences resolver →
owner_settings and connection validation. API enqueue and scheduler dispatch save
non-secret execution snapshots on runs. Worker execution uses those choices while
clamping against current limits and checking live connection authority. Usage
records preserve the original reservation for unknown consumption. Migration004
adds settings/snapshots; migration005 adds reservations. See ADR003 and SETTINGS.md.

## Supported release and retired surfaces

The five destinations are Assistant, Memory, Skills, Settings and Activity.
The supported runtime is FastAPI, React, PostgreSQL and one durable worker.
Legacy Flask code is retired from the working tree under ADR004; original Git
history and a hashed local archive retain provenance. Existing public-schema data
is untouched, and commander.cli still imports reviewed legacy JSON.
Shell execution, arbitrary HTTP retrieval, email, calendars, voice and swarms are
outside this release. ECC is retained development tooling, excluded from images.

## API and state specification

The canonical wire contract is [openapi.json](openapi.json), generated by
`uv run python -m scripts.export_openapi`. Frontend types derive from it with
`npm --prefix frontend run api:types`.

API families: `/api/auth`, `/api/memory`, `/api/conversations`, `/api/runs`,
`/api/schedules`, `/api/connections`, `/api/actions`, `/api/skills`, `/api/notes`,
`/api/worker`, `/api/budgets`. Owner authentication applies to every resource.
Cookie-authenticated writes require `X-CSRF-Token`; browser Origin must match
APP_ORIGIN. Errors have `error.code` and `error.message`; validation fields omit
submitted values. Conflicting revisions return 409; missing other-owner IDs 404.

Run states: queued → running → succeeded / failed / waiting_approval / uncertain
/ cancelled. Approval returns a waiting run to the queue. A lost external write
response becomes uncertain, never automatically retried. Action states bind
owner, run, tool, exact argument hash, configured repository, connection revision,
and a 30-minute expiry. Edits reset approval. Successful receipts record provider
object number, canonical URL and confirmation timestamp.

Memory types are explicit, inferred, episodic, task, evidence and procedural.
Only explicit/inferred preferences enter cross-session recall. Explicit entries
win on key conflicts. Expired preferences do not enter context. Raw conversations,
evidence and task outcomes live in separate relational tables, not as permissions.
No derived embedding or summary index exists, so deleted memory is immediately
absent from future recall. Old conversation messages may still mention it until
the conversation is deleted.

Budgets: step count, context characters, output tokens, run duration, daily run
count and daily model tokens are configurable. Unknown usage reserves the maximum
request allowance. Currency limits fail closed without operator-supplied model
prices. No model prices or provider usage are invented. Provider timeout is
bounded per request. Unknown cost remains null in activity diagnostics.
